## 2. Why — per-row justification with evidence

**R1 Minimal kernel. Base 1.** The eight primitives (Principal, Observation, Claim, Evidence, Justification, Revision, Knowledge Space, Knowledge View) are admirably small, but the *system* built on them is not: three logical stores over an event log, an ATMS engine, five verifier kinds, three integration tiers, agent models, federation envelopes, four auto-ingest adapters. Domain types are exiled to "ontology" in words, yet schemas, justification-combination rules and verifier governance — the parts that make the kernel mean something — are unspecified. ALT-DOC's kernel is four document kinds + a linter (2). ALT-PROJ's schemas are tiny but the projector/adapter system is real machinery (1). Hybrid keeps DOC's authoring kernel and PROJ's read model with no additional primitive kinds (2).

**R2 Reuse. Base 1.** Part 2 reuses correctly *in intent* (own journal + refs; identities/grants/journals stay with owners; board stays optional). Part 1, scored as part of the same design, still specifies a parallel stack: its own event log as source of truth ("Источник истины — Append-only Event Log (рекомендую)"), its own Principal/registry story, its own MCP service and Rust/SQLite kernel, its own federation. The platform already journals everything memory would observe — session-host journal + `resolve_ref` (`vision/contracts/handoff-package.md`), board `activity-event.v1` streams with one event per mutation in the same transaction (K7; `skill-project-management/docs/activity-mutation-coverage.md`), dispatcher effects/receipts, keeper append–fold–replay ledger, Curator locks. Copying those observations into a memory-owned log is reuse in reverse. DOC and PROJ both score 2 because neither opens a competing log of record; PROJ is maximal by construction.

**R3 Authority separation. Base 1 (not 0, not 2).** Part 2 states all four boundaries correctly: memory never computes authority from belief, never becomes a system instruction, never gets a second session input, never becomes a security dependency. That saves it from 0. It cannot score 2 because Part 1's contracts do not *enforce* those boundaries: `recall` returns knowledge packages with no required framing/provenance gate; "Native" tier promises lifecycle hooks and "active notifications"; the TMS chain ends in "Notify → orchestrator runs review-playbook" with the authorization seam left to prose. On this platform, authority lives in exact mechanisms — single stdin writer in the session host, checks "where the action happens", D-GOALS goal authorship, handoff per-item verdicts that never promote peer content into a user turn. A design scores 2 only when the dangerous path does not exist. In DOC/PROJ/hybrid it does not exist: delivery is Curator packages + handoff packages only; the only active output is a board review proposal.

**R4 Secrets and retention. Base 1.** The sketch names the right tools (retention policy, redaction, key destruction, index rebuild, honest "evidence deleted" marking) and Part 2 explicitly rejects "store everything first". But Part 1's Observation Log + four automatic adapters (conversation, tool, runtime, external) still *architecturally invite* bulk copying of transcripts/tool outputs into a logically immutable store — directly against the platform's F-1 home-deletion rationale (absence of secrets in agent-controlled bytes cannot be proved) and the handoff rule that secret-bearing material is never copied, only referenced. DOC scores 1 (prevent-by-construction, but git-history erasure is an operator rewrite — stated, not hidden). PROJ/hybrid score 2: no copied bytes exist; erasure is re-derivation from owners plus crypto-shredding of any sensitive fragment, with tombstones degrading dependent claims visibly.

**R5 Runtime independence. Base 2 — its clearest win.** MCP tools + HTTP/SDK parity, Basic/Integrated/Native tiers, honest admission that MCP cannot secretly observe a host: this is the right portability story and the alternatives should (and do) steal the façade. DOC also scores 2 (git+files+CLI run anywhere; Letta MemFS proves the shape). PROJ/hybrid score 1: the portable parts (overlay + KnowledgeView schemas + MCP façade) travel, but value outside Swarma depends on writing source adapters per environment. I accept losing this row to win R2/R4/R6; the operator should decide consciously (Q1, §6) whether "standalone open-source memory runtime first" outranks "Swarma-correct first".

**R6 Honest epistemics. Base 1.** The distinctions are excellent and I keep all of them: provenance ≠ truth ("agent A said X" ≠ "X"), epistemic vs verification vs decision status, Belnap four values, bitemporal time, propose-don't-assert, "issued ≠ used as premise". Two overclaims cap the score. (a) *ATMS completeness:* full ATMS maintains minimal assumption environments whose worst case is exponential (2^n environments; generating minimal supports is NP-hard — de Kleer 1986 lineage; UBC TR-88-11; Temple CIS587 notes; accessed 2026-10-14). The sketch hedges ("bound explanation size, local recompute") but then the metric "Invalidation correctness — *all* affected conclusions revised" is no longer claimable; the bounded semantics that *would* make it honest are never specified. (b) *LLM extraction + verification theatre:* with LLM-based observation→claim extraction and an LLM "semantic reviewer" in the loop, a `supported` status can be manufactured from fluent nonsense unless derivation rules are mechanical. DOC scores 1 (mechanical derivation, but NL bodies allow vague claims). PROJ/hybrid score 2: Belnap is *derived* from evidence stances by a closed rule, evaluation is lazy/bounded with `needs-review` overflow, completeness is claimed only over registered links, and every view is pinned to source watermarks so stale can never pose as current.

**R7 Specifiability. Base 1.** Metrics are well chosen (recall/evidence precision, temporal accuracy, invalidation correctness, false-invalidation, leakage, cost) — I adopt them. But there is no closed grammar yet: claim schema is an example, justification combination (`(A∧B)∨(D∧E)`) has no evaluation rules for partial/stale/conflicted premises, verifier pass/fail semantics are prose, and ontology governance ("who may add a schema/predicate?") is absent. No conformance vector could be written against the sketch today without inventing semantics. DOC/PROJ score 1 for mirror reasons (closable, not yet closed; PROJ additionally waits on unpublished source APIs). Hybrid scores 2 *conditionally*: its grammar is small enough that the RFC in §3 can and must ship vectors (valid/invalid documents, evaluation cases, redaction drills, leakage negatives) — if it doesn't, the score falls to 1.

**R8 Incremental value. Base 1.** P0 (SQLite log + typed claims + MCP) would function as a decision log, so not 0 — but it is a *worse* decision log than the board+git the platform already runs, and everything distinctive (TMS P1, proofs P2, federation P3) arrives later. The sketch's own best first use — Swarma architecture decision memory (Part 2 §5, the F-1 worked example) — needs none of P0's kernel. DOC/hybrid score 2 because that exact slice ships first and pays alone; PROJ alone scores 1 (needs extractors wired before first value).

## 3. Recommended design: "Refs, not copies" — projection + document overlay (`swarma-memory` as a client, not a store of record)

Enough detail to start an RFC. In one paragraph: **keep the base's semantics, delete its store.** Claims, evidence refs, justification links and revision proposals are typed git documents governed by the board (ALT-DOC surface); all observation bytes stay in their owners' journals; a deterministic projector builds a disposable index over board + git (+ later host/dispatcher/keeper/a2a) and composes watermark-pinned KnowledgeViews at read time (ALT-PROJ engine); delivery to agents happens only as Curator-approved standing packages or handoff task slices; truth maintenance is bounded lazy evaluation over registered links emitting board review proposals. If a service process is wanted later, it is the projector/indexer under its own unprivileged account (`swarma-memory`) owning *only* the disposable index — killing it loses a cache, never knowledge, and never blocks stop/revoke/recover paths.

### 3.1 Primitives (closed kernel — four kinds, three statuses, two times)

1. `Claim {id, schema, subject, predicate, object|statement, perspective, valid_from, valid_to}` — statement schemas registered per domain (JSON Schema; SHACL only if a schema owner demands it). IDs are stable and content-independent (`claim:<slug>`); bodies may include short reviewed quotations, never transcripts.
2. `EvidenceRef {id, claim, stance: for|against, kind, ref, digest, span_hash?, observed_by (keeper identity), recorded_at}` — `ref` grammar is closed: `git:<repo>@<commit>#<path>`, `board:<element>@<activity_seq>`, `host:<session>/<journal_seq>`, `dispatch:<effect_id>`, `keeper:<seq>`, `a2a:<room>/<event_id>`, `artifact:<digest>`, `attestation:<envelope_ref>` (incl. in-toto/DSSE as referenced kinds). PROV-O mapping (Entity/Activity/Agent) is an export view, not the storage model.
3. `Justification {claim, alternatives: [premise_set+], rule}` — OR of ANDs over Claim/EvidenceRef ids; justification graph must be a DAG (enforced on write); `rule` from a closed registry (`cite`, `test-passes`, `decision-adopts`, `attested-outcome`, …) each with a deterministic evaluation rule.
4. `Revision {supersedes, superseded_by, reason_ref, decided_by, decided_at}` — append-only; old claims are never edited into new meanings.

Statuses, stored vs derived (this separation is the kernel's honesty mechanism):
- **Decision status** `proposed|adopted|superseded|rejected` — *stored*, writable only by board transition / operator-signed record. Memory code never writes it.
- **Verification status** `unchecked|source-checked|signature-checked|outcome-checked|formally-checked` (+ `unverifiable: evidence-deleted|source-unavailable`) — *computed at view time* by the three deterministic verifiers (source/digest; signature+grant-chain via the platform verification library; exact-quadruple outcome attestation). Never stored as a flag an agent can set.
- **Epistemic status** `unknown|supported|refuted|conflicted` (Belnap) — *derived* by a closed rule from EvidenceRef stances whose verification ≥ `source-checked`, evaluated within the claim's perspective. No evidence ⇒ `unknown`, full stop. LLM judgements carry stance `none` and can only create challenges.

Times: valid time (`valid_from/to`, domain) + transaction time (git/board/source watermarks). Every KnowledgeView pins both: `{as_of_valid, at_watermarks: {repo_commit, board_seq, host_H, …}}`.

Evaluation rule (the bounded TMS replacement, to be fixed in the RFC with vectors): a justification set is *intact* iff every premise claim is decision-`adopted` (or, for non-decision claims, epistemic `supported`) and no premise evidence is `unverifiable`; a claim is *standing* iff ≥1 alternative set is intact; *fallen* iff all sets are broken by superseded/refuted premises; otherwise *needs-review* (includes bound overflow: defaults max 8 premises/set, 8 sets, depth 6 — operator-tunable per space, overflow never guesses). Source change ⇒ reverse-reachability over registered links ⇒ board `needs-review` elements naming the changed premise and affected claims. Nothing auto-supersedes.

### 3.2 Stores and single writers

| Store | Single writer | Memory's relation |
|---|---|---|
| Session-host journal + protected storage | `swarma-session-host` | Read via typed API; bytes via audited `resolve_ref` only |
| Board store + activity streams | Board kernel | Decisions, goal revisions, review queue, overlay element types (ClaimProposal/Challenge where hosted as elements) |
| Dispatcher / broker / user-manager records | Those services | Read receipts/verdicts; never consulted for *belief*, only for *outcome evidence* |
| Keeper ledger | Keeper module (deterministic) | Read obligations/handoffs as evidence |
| a2a rooms (waggle envelopes) | Room participants under waggle verification | Signed decision/approval records as evidence; envelopes for export |
| Memory document repo (git) | Board-governed change-request path (K1–K5, signed fast-forward) | Claims/refs/links/revisions — the only memory-authored store of record |
| Projection index (SQLite) | Indexer process | Disposable cache at named watermarks; safe to delete/rebuild anytime |

Identities: existing keeper-derived agent identities; writers identified by kernel peer credentials / signed commits, never by self-claimed fields. Grants: new actions `memory.read|propose|challenge|export` (+ per-space targets) registered through the existing handler-manifest → namespace → grant procedure; checks at the board/host boundaries where effects happen. Knowledge Spaces = (repo + board partition + grant target set); personal/project/shared differ by grants and repo, not by code.

### 3.3 APIs (CLI canonical; MCP/HTTP are façades over the same verbs)

`memory propose` (open a change request; agents never write adopted state) · `memory search` · `memory expand <claim>` (explain: justification unfolding to resolved evidence, one level per call) · `memory verify <claim>` (run verifiers, return report with per-ref outcomes incl. `not established`) · `memory challenge <claim>` (open board review) · `memory changes --since <watermarks>` (source diffs + stale flags) · `memory forget <ref>` (redaction workflow: source-owner erasure request → tombstone → index rebuild → dependents degraded). `observe` from the base survives only as "propose an EvidenceRef to an existing owner record" — there is no endpoint that ingests raw bytes into memory. All agent-facing output is framed `data` with provenance labels; promotion to instruction requires the Curator approval path, always.

### 3.4 Platform seams (what touches what — and what never does)

- **Curator:** standing knowledge ⇒ context package version, pinned in profile locks, weight below role modules. Memory never edits a profile; it *proposes* package content through the normal audit/approval flow (incl. CIP-0013-style machine base discipline if adopted: opt-in, package-sourced, lock-approved).
- **Session host / context engine:** memory is *not* in the host and adds nothing to it. Task knowledge ⇒ handoff items (`swarm-handoff/2` allowlist; per-item `provenance`; audience-bound; re-authorized at seed). Memory never enqueues session input, never wakes, never nudges (goal provider/scheduler unchanged).
- **Board:** adoption/supersession/review are board transitions under K1–K8; `needs-review` is a board element; agent "done"/outcome semantics unchanged. Board remains optional to the platform; memory-without-board degrades to git-docs + operator-signed decisions (same schemas).
- **Dispatcher/broker/user-manager/keeper(keys):** read-only evidence sources. Memory outage must not affect launch/stop/revoke/reconcile — enforced by having no call *from* those services *to* memory.
- **Distributed protocol / substrate (later):** outcome attestations and reputation inputs are *consumed* as evidence; agent models are perspective-scoped claims over receipts; no central score, no on-chain private graphs (digests/pointers only, per book ch. 16). Federation = signed Knowledge Envelopes over waggle/a2a with distinct read/use/retain/forward grants, imported as quarantined proposals.

### 3.5 Explicitly out of scope (v1)

No ATMS/label engine; no graph database (Graphiti admissible later *only* as a disposable projection backend behind the same view API, with its LLM extraction quarantined to proposals); no vector store as authority (embeddings, if used for search ranking, live in the disposable index and never affect statuses); no automatic transcript/tool-output ingestion; no theorem provers; no memory-driven orchestration; no global reputation; no new transport (MCP is one façade; A2A/waggle carry federation).

## 4. Smallest change set from the base to the recommendation

1. **Delete the memory-owned Event/Observation Log as a store of record.** Observations become EvidenceRefs to owner journals. (Part 2 already walks half this distance; finish it.) — *R2, R4.*
2. **Replace "ATMS with bounded explanations" with the specified lazy/bounded evaluation + board review queue** (§3.1), and correct the invalidation metric to "100% over registered links; unregistered dependencies are candidates, never guarantees". — *R6, R7.*
3. **Make the three statuses stored-vs-derived as in §3.1** (decision stored by board only; verification/epistemic computed). This is a one-paragraph change to the base that removes most poisoning surface. — *R3, R6.*
4. **Restrict delivery to Curator packages + handoff packages;** demote `recall` to a framed read tool; delete the Native hooks/active-notify tier from v1 (board `needs-review` is the only active output). — *R3.*

Defer Proof-Engine plugins beyond the three deterministic verifiers, agent-model queries beyond receipt-backed claims, and all federation beyond signed envelope *format* definition. — *R1, R8.*

## 5. First slice (MVP) — useful alone on one host

**Name:** Swarma decision memory. **Users:** orchestrators/workers on architecture tasks; reviewers. **Scope:** schemas for Decision/Finding/SpecVersion claims; memory repo seeded from the book + review findings (incl. the F-1 home-deletion decision as the worked fixture); deterministic extractors for git + board activity only; linter (schemas, digests, DAG, stale scan); `search|expand|verify|changes` CLI; KnowledgeView delivery via handoff packages; `needs-review` board feed on supersession. No new daemon (indexer is a CLI/cron-style job), no session-host changes, no dispatcher changes.

**Value measurement (pre-registered, falsifiable):** (1) *Answer quality:* 20 sampled "current decision + why + replaced what + dependents" questions answered by fresh agents with vs without the view — score correctness + evidence precision (cited refs actually support the claim; target ≥95%, else fix schemas/extractors). (2) *Staleness drills:* supersede 5 fixture decisions — require 100% registered-dependent flagging, report false positives, require zero superseded decisions served as current. (3) *Authority audit:* grep session transcripts — memory text must never appear unframed as instruction; any hit fails the slice. (4) *Cost:* index rebuild time + view latency/token size vs book-search baseline. If (1) shows no improvement, the honest conclusion is that documents+board *without* the projector (pure ALT-DOC) suffice — the slice is designed so that fallback keeps all authored value.

**Slice 2 (only on slice-1 evidence):** add session-host/dispatcher/keeper sources behind their published APIs; outcome-backed AgentModel claims; Curator standing-package promotion flow. **Slice 3 (only on demand):** Graphiti/materialized backend bake-off as index replacement; federation envelopes between two owners/hosts (the platform's federation reference test shape: two Matrix servers, two roots).

## 6. Questions only the operator can decide

- **Q1 Product intent:** is the goal (a) a Swarma-correct memory first (this verdict's assumption), or (b) a standalone open-source "Universal Agent Memory" runtime that Swarma merely adopts first? - **Q2 Decision authority for knowledge:** may claim *adoption* live on the board (my recommendation), or is a lighter operator-signed git-only path required for board-free/personal use from day one? This decides whether the overlay needs its own store anywhere.
- **Q3 Erasure promise:** is "prevent secret bytes from ever entering documents; erasure = owner deletion + tombstone + rebuild (git history rewrite only by operator act)" an acceptable retention contract, or must v1 promise routine history-level erasure (which would force a different store)?

- **Q5 Naming/placement:** if/when the projector becomes a service, confirm `swarma-memory` as repo/binary/account under the one-name rule — owning only the disposable index — vs keeping memory a pure library/CLI inside the board's orbit.
