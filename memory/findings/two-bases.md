# Finding: the sketch's Part 1 and Part 2 specify different systems; proof needs one defined base

- Lens: rubric and proof (wonder-04). Status: `proposed`.

## Problem

The base design is two documents with different delivery plans and different risk postures:

- Part 1 (standalone Universal Agent Memory): P0 Rust kernel + SQLite + MCP server, P1 full truth
  maintenance (ATMS), P2 proof-carrying verification, P3 federation; automatic capture from
  conversation, tool, runtime and external adapters.
- Part 2 (Swarma embedding, later): three reduced stages beginning with decision/evidence memory
  over documentation and admitted board results; admitted sources only; "no need to fix full ATMS,
  a graph DBMS, own federation and a mandatory theorem prover now"; own journal plus references
  instead of one global log.

Seats scoring "the base" have therefore scored different objects. The observed round-1 base totals
(9–13 across seats) are explained almost entirely by this fork plus one-point convention
differences, not by factual disagreement: every checkable platform claim in the sketch is confirmed
in substance by independent mechanical checks in two fives. In particular, the only two-point
per-row spread (base R8: 0 vs 2) is exactly "Part 1 staging" vs "Part 2 staging".

## Evidence

- SKETCH Part 1 §§4–10 vs Part 2 §§3, 8 (texts in `memory/inputs/SKETCH.ru.md`).

## Proposed change

The collective (and any successor RFC) adopts: **Part 2 is the normative base; Part 1 is background
requirements.** Rubric tables state which object they scored; "Part 1 alone" deltas are recorded as
footnotes, not silently mixed into conjunction totals. Part-1-only commitments (automatic capture,
ATMS-first ordering, Rust/MCP-first P0, federation in scope) do not bind the recommended design
unless re-adopted explicitly with their rubric cost shown.
