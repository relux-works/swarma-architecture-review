# Profiles use case against the contract: what holds, what to amend

Input: `memory/inputs/USECASE-PROFILES.ru.md` (operator-supplied, 2026-10-17): typed profiles of people and autonomous agents, delegated updates, publication to a shared space, discovery and introductions. The analysis inside it proposes six contract amendments and nine test cases. This note checks them against `designs/bounded-evidence.md` @ 5d96e70 and `designs/bounded-support-semantics-astra-03.md` @ 9bafff8, and against decisions D-001…D-007. Written by the memory lane orchestrator. Status: proposed; nothing here is adopted.

## Verdict

The use case is the first real test of D-002 (a portable kernel whose generality must show in behaviour, not only in the ability to store any fields). The five records hold; no `Person`, `Profile`, `Intent` or `DiscoveryCard` primitive enters the kernel. Two amendments belong in the kernel and also help the architecture-decision pilot: attribution roles (A2) and current-state projection with freshness (A3). Two are boundary contracts the kernel must define but not own: derived disclosure (A4) and the view-to-publication handoff (A5). Schemas (A1) reinforce a gap already found by review 1. Staging (A6) agrees with D-003, D-004 and D-006 as they stand. Intent, matching, catalogs, introductions, contact policy and any blockchain role stay in a domain layer above memory and are out of scope for the R7 package.

## Safety notes for the domain layer (not the kernel)

Relationship status, romantic intent and location are high-risk personal data: exposure enables stalking and harassment. Defaults for that layer: no exact location in any public card; romantic introductions only as an explicit opt-in mode for adults, never inferred from relationship status; mutual consent before any contact details; a public "we are partners" link only when both sides confirm. None of this ever goes into the git register (D-003); it waits for the protected service (D-006) and its own security qualification. Per DID Core, no personal data in public DID documents and no hashes of low-entropy personal fields.
