# C3 — Bind Codex overrides through curator-run and tracked delivery

- **Owner repository:** curator-agent-launcher.
- **Normative clauses:** profile-codex-settings §§3–7; CIP-0018 leaf 4;
  environments §10.2 and the coordinated successor carrier publication.
- **Attack surface:** strict fragment policy surviving direct/tracked launch.
- **Size:** M.

## Acceptance and paired tests

Consume the published successor with a strict whole-object decoder, preserving
the accepted typed object and profile lock identity. Invoke C2 through the
existing plugin request, not a second TOML serializer. Preserve settings in
fragment digest, sealed plan and tracked request; relay receives the covered
payload without re-resolution or home inspection. Plain env/shell output is
not an alternate settings transport.

- Valid interactive/exec/direct/tracked cases observe exact child argv and
  unchanged config bytes. Unknown revision, duplicate member, missing required
  payload or unsupported plugin refuses before exec without downgrade.
- Altered/removed settings, selection mismatch or digest mismatch refuses;
  unchanged covered request succeeds. Test removal as well as value mutation.
- Native raw/profile aliases that compete refuse even when equal; unrelated
  allowed native arguments succeed. Do not erase policy after an argv boundary.
- Cold/new session uses its accepted policy; incompatible reuse/resume cannot
  silently inherit a later machine selection. Preserve the explicit transition
  or refusal handed to the host owner.
- Plant a tracked-path-only payload omission: captured destination policy must
  make the end-to-end checker fail. Direct-path success cannot mask it.

## Dependencies, paths and cross-repository handoff

Depends on carrier publication, C2 release and C1-compatible fixtures. Serialize
with M4 on `SPEC.md`, `internal/fragment/`, `internal/plan/context.go`,
`internal/composition/`, `internal/execution/`, `go.mod` and `go.sum`.

**Separate required owners:** skill-project-management must adopt the same
typed payload at app-server, client, reuse and resume boundaries (CIP-0018
leaf 5), preserving private tool policy and exclusive MCP base construction;
swarma-dispatcher must relay it unchanged and reject missing/tampered payload
(leaf 6). Astra-04's hosted leaves own those implementations. The snapshot
descriptor does not itself cover credential backend/settings: explicit plan
coverage is still required. Producer enablement waits for these advertised
routes; this leaf cannot declare them qualified by association.
