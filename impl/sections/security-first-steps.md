## The one rule this section applies

Admission of an external contributor is not one switch. It is the last of three thresholds, and each threshold is proved by refusals, not by a successful run:

| Threshold | What is admitted | Owner's own words and the governing texts |
|---|---|---|
| **T0: a protected launch of our own agent** (S0a, then S0b) | One trusted-class local agent under its own OS account, started only by the dispatcher through the root launcher, with the operator principal outside every agent account. | CB7 §16 slice 0; CIP-0009 `:273` "Slice 0, the one-host MVP (F25), before any donor"; F-4, F-6, F-23. |
| **T1: enforced boundaries for our own agents** (S1 credential mechanism, S2 enforced networking) | Trusted-class agents whose egress, executables, ceilings, sockets and standing surfaces are enforced by the kernel and verified by the platform, with the abuse controls that act without a person. | CB7 §16 slices 1 and 2; DP7 §13; UM7 §§7–8; decisions `:681-694` (items 1–11 of the infrastructure review accepted). |
| **T2: the first external contributor** (milestone A) | One remote worker in a `workplace` account: untrusted class, zero egress, no credentials, no loop, whose code leaves only through R-TRANSFER and is reviewed as exactly C. | DP7 §14 rows "workplace", "cross-account workspace", "untrusted admission", "verification", "key keeper"; CIP-0009 `:275` "the one-host slice 0 alone does not activate workplaces"; decisions `:669-677` (R-TRANSFER), `:678` (zero egress), `:680` (no loop here). |

T0 never claims T2. The texts say so twice: CB7 §16 ("Later untrusted placement requires v1 and a qualified host matrix, exec profile, workplace zero egress, R-SOCKETS declared-socket reachability and R-SHARED deployment separation") and CIP-0009 `:275`. A plan that lets a passing S0 stand in for "ready for donors" is the single most expensive mistake this lens can prevent.

**Where S0a ends and S0b begins.** Rows 0.1–0.8 are the protected-launch core (S0a, CB7 §16 slice 0). CIP-0009 `:273` additionally requires separate keeper, broker and worker identities, a composed-plan host, a durable mailbox with exact-byte signatures and one task spanning the chain of OS users; CB7 §17 and DP7 §14 put the key keeper behind its own publication gate (registration tuples `(uid, generation, identity path, owner, registration generation)`). From the security lens the keeper is a **T2** prerequisite, not a T0 one: no internal launch needs agent identities as keys, but every envelope a remote worker verifies does. Treat S0b as "S0a plus the keeper and mailbox publication", and do not start T2 work on the mailbox or the keeper before their formats are frozen. Nothing in S0a or S0b activates a workplace.

## Credential leasing and the operator boundary, in one picture

1. **Root of trust.** The v0 root is a software key in `swarma-operator` (F-23). Hardware custody is a later root-format decision, not a T0 prerequisite. The keeper becomes the trust root at T2 (CB7 §17).
2. **Who may hold what.** Trusted-class local agents receive a leased token through the executor path only (UM7 `:431`, CB7 §12.1, readable by its holder: an accepted limit). Workplaces never receive a lease or a binding (CB7 `:611`). Remote workers use their own provider credentials on the donor machine (CIP-0010); nothing is stored for them on our side.
3. **How authority ends.** Revocation verdicts are narrow and published (F-8); restore is fenced until revocation history is acknowledged (F-9); delivered vendor tokens keep their vendor lifetime, which local revocation cannot erase (accepted limit); renewal of standing authority is a human-presence act before the horizon (F-14, F-23 consequence 5).
4. **Who acts.** Every widening act is authenticated and content-confirmed; every narrowing act is authenticated; both are refused inside agent sessions (DP7 `:114`, UM7 `:112`). The observer account reads and never acts.
5. **What a compromised piece can reach.** A prompt-injected trusted agent holds its own lease and nothing more; a compromised bridge signs only under its own identity until delegated keeper signing is specified ([f-mailbox-figure-verdicts](../../cycle3/findings/f-mailbox-figure-verdicts.md)); a compromised workplace can write its workspace and talk to its relay, and its only exit is a candidate that a trusted reviewer reads as data.

## What we deliberately do not build before T2

- Any web tool or search opt-in. Tasks carry their resources read-only by digest (decisions `:730`; CIP-0009 `:203-205`). The trusted-circle opt-in is a T2+ operator act, and its donor-side options are unqualified.
- Delegated keeper signing, agent self-goals, any goal-status or board-free done API ([f-agent-goal-authority](../../cycle3/findings/f-agent-goal-authority.md)).
- Launch tickets, a second privileged executor, a command-mode dispatcher, an interim board receiver, a same-UID refresh owner (F-4; decisions `:736`; lens 3).
- Cooperative-only networking presented as containment. N15 item 9 records earlier profiles as declared, not enforced; nothing admitted at T2 may rest on a declared row.
- A general plugin bus, a universal mailbox, or a platform web-tool service before an opted-in trusted-circle consumer exists.
- Variant B or C donor deployments, and any Windows path.

## Risks specific to security sequencing

1. **S0 mistaken for readiness.** The owner's own MVP text says "before any donor"; the plan must repeat that no T0 evidence admits a workplace.
2. **Task tooling before the exec-policy relation.** Interpreter-bearing profiles built before row 1.4 will be rebuilt; freeze the relation first, then ship profiles.
3. **A reviewer harness that discovers candidate files.** The flagged-hunk acknowledgement cannot protect a reviewer whose harness loaded the candidate's hooks first; the data-only consumer (row 2.7) is cheaper than a strict adapter and must come first.
4. **Declared networking treated as enforcement.** Any T2 row resting on a cooperative profile is a false pass; the capability matrix row must be hard.
5. **Status-only alerting that nobody declared.** An abuse control whose purpose is to summon the operator must say in which version the operator is summoned; otherwise the watcher's narrowing is the only real control.
6. **Operator attention as an unbounded resource.** Flagged hunks, export waivers, refusal dispositions and alerts all summon the operator; T2 should admit one worker and one task class until the per-round operator load is measured.
7. **Formats frozen against moving decisions.** `workspace-result/1` is DRAFT; the join objects are pending; the keeper registration is gated. Code written against drafts is the rework the owner asked us to avoid; the freeze order is lens 2's, and this section only states which freezes T2 waits for.
