## The rule this section applies

Every security gate binds at its **first use**, not at the first external contributor. UM7 `:401` requires the recorded class, the qualified host matrix, the task exec profile and the selected R-CEILINGS/R-EXEC/R-NET-TOOL restrictions before any child code of any managed start; UM7 `:437` applies R-EXEC to every agent or workplace task class; CB7 `:820` puts journaled R-ALLSTOP and its recovery inside the protected Claude slice; UM7 `:441` applies the standing-surface digests before the first standing launch. The external contributor is therefore the last rung of a ladder whose lower rungs already carry most of the security work. A plan that labels those rungs "later, for donors" builds S0 twice.

## Credential leasing and the operator boundary, in one picture

1. **Root of trust.** The v0 root is a software key in `swarma-operator` (F-23). Hardware custody is a later root-format decision, not an S0a prerequisite. The keeper becomes the trust root at S0b (CB7 §17).
2. **Who may hold what.** Trusted-class local agents receive a leased token through the executor path only (UM7 `:431`, CB7 §12.1), readable by its holder, an accepted limit. Workplaces never receive a lease or a binding (CB7 `:611`). Remote workers use their own provider credentials on the donor machine (CIP-0010); nothing is stored for them on our side.
3. **How authority ends.** Revocation verdicts are narrow and published (F-8); restore is fenced until revocation history is acknowledged (F-9); delivered vendor tokens keep their vendor lifetime, which local revocation cannot erase, an accepted limit; renewal of standing authority is a human-presence act before the horizon (F-14, F-23 consequence 5).
4. **Who acts.** Every widening act is authenticated and content-confirmed; every narrowing act is authenticated; both are refused inside agent sessions (DP7 `:114`, UM7 `:112`). The observer account reads and never acts. Local operator and broker grants are closed sets; they are not a reason to build universal delegation or a second authority service.
5. **What a compromised piece can reach.** A prompt-injected trusted agent holds its own lease and nothing more; a compromised bridge signs only under its own identity until delegated keeper signing is specified ([f-mailbox-figure-verdicts](../../cycle3/findings/f-mailbox-figure-verdicts.md)); a compromised workplace can write its workspace and talk to its relay, and its only exit is a candidate that a trusted reviewer reads as data.

## What we deliberately do not build before A

- Any web tool or search opt-in. Tasks carry their resources read-only by digest (`decisions.md:730`; CIP-0009 `:203-205`). The trusted-circle opt-in is a post-A operator act, and its donor-side options are unqualified.
- Delegated keeper signing, agent self-goals, any goal-status or board-free done API ([f-agent-goal-authority](../../cycle3/findings/f-agent-goal-authority.md)).
- Launch tickets, a second privileged executor, a command-mode dispatcher, an interim board receiver, a same-UID refresh owner (F-4; `decisions.md:736`; lens 3).
- Cooperative-only networking presented as containment. N15 item 9 records earlier profiles as declared, not enforced; nothing admitted at A rests on a declared row.
- A general plugin bus, universal delegation, a platform web-tool service before an opted-in trusted-circle consumer exists.
- Variant B or C donor deployments, and any Windows path.

## Open owner decisions this lens does not make

Platform metadata visibility to tenants (A.10); local-only reviewers and requester-orchestrator exclusion ([f-trusted-circle-class](../../cycle3/findings/f-trusted-circle-class.md) item 5); CONNECT application-origin confinement beyond authority checks ([f-connect-origin-boundary](../../cycle3/findings/f-connect-origin-boundary.md)); standing discard of refused rounds (W.4); soft-row acceptance per host (0.6); delegated keeper signing (1.3); hardware root custody; the non-workspace intake publication (0.1). Each is listed as a decision, not as an adopted activation rule.

## Risks specific to security sequencing

1. **S0a mistaken for readiness.** The owner's MVP names Claude and Codex and says "before any donor"; the plan must repeat that no S0a evidence admits a workplace, and no S0b evidence either.
2. **Task tooling before the exec-policy relation.** An interpreter-bearing profile built before row 0.5 will be rebuilt; freeze the relation first, then ship profiles one qualified row at a time.
3. **A reviewer harness that discovers candidate files.** The flagged-hunk acknowledgement cannot protect a reviewer whose harness loaded the candidate's hooks first; the data-only consumer (L.2) is cheaper than a strict adapter and must come first.
4. **Declared networking treated as enforcement.** Any A row resting on a cooperative profile is a false pass; the capability row must be hard.
5. **Status-only alerting that nobody declared.** A control whose purpose is to summon the operator must say in which version the operator is summoned; until then the watcher's narrowing is the only real control.
6. **Operator attention as an unbounded resource.** Flagged hunks, export waivers, refusal dispositions and alerts all summon the operator; A should admit one worker and one task class until the per-round operator load is measured.
7. **Formats frozen against moving decisions.** `workspace-result/1` is DRAFT; the join objects are pending; the keeper registration is gated; the non-workspace intake is unpublished. Code written against drafts is the rework the owner asked us to avoid; the freeze order is lens 2's, and this section only states which freezes each rung waits for.
